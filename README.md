# کابینت‌پلن — CabinetPlan-FA

طراحی دوبعدی کابینت با رابط کاملاً فارسی، روی گوشی اندروید و بدون نیاز به رایانه.

[![ساخت اندروید](https://github.com/gase99/DarwPlan-2Dpro/actions/workflows/android-build.yml/badge.svg)](https://github.com/gase99/DarwPlan-2Dpro/actions/workflows/android-build.yml)

## وضعیت فعلی: فاز ۱

این پروژه فعلاً در مخزن عمومی **gase99/DarwPlan-2Dpro** توسعه می‌یابد؛ نام اپ و پروژهٔ اندروید **CabinetPlan-FA** است. محدودیت نشست اجازهٔ انتقال توسعه به مخزن یا شاخهٔ دیگری را نمی‌دهد.

- رابط فارسی با ارقام فارسی و چیدمان راست‌به‌چپ، حتی روی گوشی انگلیسی‌زبان
- بوم شبکه‌ای دوبعدی با واحد میلی‌متر و نمایش مبدأ
- جابه‌جایی با کشیدن یک انگشت و بزرگ‌نمایی با دو انگشت، حول نقطهٔ لمس
- دکمه‌های بزرگ‌نمایی، کوچک‌نمایی، بازنشانی نما و راهنما
- پشتیبانی از حالت روشن و تیره
- معماری MVI با `ViewModel` و `StateFlow`، تزریق وابستگی Hilt و زیرساخت Room
- ساخت خودکار APK آزمایشی، آزمون‌های واحد و Android Lint در GitHub Actions

**هنوز امکان رسم خطوط، چیدن کابینت، ذخیرهٔ طرح یا خروجی گرفتن وجود ندارد.** زیرساخت Room آماده است، اما رابط ذخیره/بارگذاری در فاز ۴ اضافه می‌شود. وضعیت نما در چرخش صفحه حفظ می‌شود؛ پس از بسته‌شدن فرایند اپ تضمینی برای حفظ آن نیست.

حداقل نسخهٔ موردنیاز: **اندروید ۸٫۰ (API 26)**. اپ مجوز اینترنت یا دسترسی عمومی به فایل‌ها درخواست نمی‌کند و کاملاً محلی است.

## دریافت نسخهٔ آزمایشی با گوشی، بدون رایانه

۱. وارد حساب GitHub خود شوید و [صفحهٔ ساخت‌ها](https://github.com/gase99/DarwPlan-2Dpro/actions/workflows/android-build.yml) را باز کنید.
۲. آخرین اجرای موفق مربوط به شاخهٔ توسعه را که علامت سبز دارد انتخاب کنید.
۳. در بخش **Artifacts**، فایل `CabinetPlan-FA-phase1-debug` را دریافت کنید. فایل خروجی یک ZIP است؛ با برنامهٔ فایل‌های گوشی آن را باز و `app-debug.apk` را استخراج کنید.
۴. روی APK بزنید. اگر اندروید اجازه خواست، فقط برای مرورگر یا برنامهٔ فایل‌هایی که استفاده می‌کنید، «نصب برنامه‌های ناشناس» را فعال کنید.
۵. پس از نصب، بهتر است این اجازه را دوباره غیرفعال کنید. فقط APK همین مخزن را نصب کنید؛ محافظت Play Protect را غیرفعال نکنید.

خروجی هر ساخت ۳۰ روز نگهداری می‌شود. اگر منقضی شده بود، از تب Actions و گزینهٔ **Run workflow** یک ساخت تازه اجرا کنید؛ نیازی به محیط توسعهٔ محلی نیست. گزارش آزمون و Lint هم با نام `android-quality-reports` قابل دریافت است.

نسخهٔ Debug برای آزمایش است، نه انتشار نهایی. امضای Debug روی اجراکننده‌های ابری ممکن است متفاوت باشد؛ اگر هنگام به‌روزرسانی خطای ناسازگاری امضا دیدید، نسخهٔ آزمایشی قبلی را حذف کنید. **حذف اپ داده‌های محلی آن را پاک می‌کند.** امضای پایدار انتشار در فاز ۵ تنظیم می‌شود.

## دریافت نسخهٔ نهایی از Releases

**هنوز نسخهٔ نهایی `v0.1.0` منتشر نشده است.** پس از تکمیل فازها و تأیید پایداری، APK امضاشده به [صفحهٔ Releases](https://github.com/gase99/DarwPlan-2Dpro/releases) افزوده می‌شود:

۱. نسخهٔ `v0.1.0` را باز کنید.
۲. از بخش **Assets** فایل `CabinetPlan-FA-v0.1.0.apk` را بگیرید، نه فایل‌های Source code.
۳. با همان مراحل نصب بالا، فایل را مستقیم روی گوشی نصب کنید؛ دریافت نسخهٔ عمومی Release نیاز به حساب GitHub ندارد.

## کار با بوم

- یک انگشت: جابه‌جایی؛ دو انگشت: تغییر مقیاس بین ۲۵٪ و ۸۰۰٪.
- `+` و `−`: تغییر مقیاس حول مرکز صفحه؛ دکمهٔ خانه: بازگشت به نمای اولیه.
- فاصلهٔ خطوط شبکه: ۵۰ میلی‌متر؛ دو خط پررنگ، محورهای مبدأ هستند.
- رابط و ترتیب کنترل‌ها راست‌به‌چپ است. خود بوم مثل کاغذ عمل می‌کند: حرکت دست به راست، بوم را به راست می‌برد و هندسه معکوس نمی‌شود.
- این نسخه فقط نمایش بوم است؛ مقیاس بوم بیانگر مقیاس فیزیکی نمایشگر یا دقت اندازه‌گیری گوشی نیست.

## ساخت و آزمون ابری

در هر push شاخه و هر Pull Request، گردش‌کار `.github/workflows/android-build.yml` این مراحل را انجام می‌دهد:

- آماده‌سازی Java 17، Android SDK 35 و Gradle Wrapper 8.9
- اجرای `testDebugUnitTest`، `lintDebug` و `assembleDebug`
- بارگذاری APK قابل نصب و گزارش‌های کیفیت

هیچ فایل کلید امضا، رمز یا `local.properties` نباید وارد Git شود. انتشار نهایی و نگهداری امن کلید امضای پایدار در فاز ۵ تکمیل می‌شود؛ برای فاز ۱ هیچ Secret لازم نیست.

برای مشارکت توسعه‌دهندگان (اختیاری، نه موردنیاز کاربر گوشی):

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
```

## ساختار کد

- `domain/Viewport.kt`: ریاضیات خالص تبدیل مختصات، جابه‌جایی و بزرگ‌نمایی محدودشده
- `ui/canvas/CanvasViewModel.kt`: حالت تغییرناپذیر و Intentهای MVI
- `ui/canvas/CanvasScreen.kt`: نمایش بوم Compose و ارسال Intentهای لمس
- `data/` و `di/`: پایگاه Room، DAO اولیه و وابستگی‌های Hilt؛ هنوز بدون رابط ذخیره‌سازی
- `res/values-fa/strings.xml`: همهٔ متن‌های رابط به فارسی؛ `values/strings.xml` نیز fallback فارسی است.
- `src/test/`: آزمون تبدیل مختصات، حفظ نقطهٔ لمس، حدود بزرگ‌نمایی، ابعاد و انتقال حالت

## برنامهٔ فازهای بعد

۱. **فاز ۱:** زیرساخت، بوم و CI — موضوع این تغییرات.
۲. **فاز ۲:** رسم خط، چسبیدن به رأس‌ها و کتابخانهٔ اشیای فارسی با کشیدن و رهاکردن؛ آزمون منطق Snap.
۳. **فاز ۳:** انتخاب چندگانه، جابه‌جایی گروهی، راهنمای هم‌ترازی و واگرد/بازانجام.
۴. **فاز ۴:** ذخیره/بارگذاری واقعی با Room و خروجی PNG؛ PDF نیز پیش از انتشار نهایی پیگیری می‌شود.
۵. **فاز ۵:** پالایش رابط و آزمون روی دستگاه، گردش‌کار انتشار مبتنی بر تگ، امضای پایدار و Release عمومی `v0.1.0`.

پس از هر فاز برای بازخورد توقف می‌کنیم؛ تا تکمیل قابلیت‌ها، این نسخه MVP نهایی محسوب نمی‌شود.

## بررسی پیشنهادی روی گوشی

- زبان سیستم را انگلیسی بگذارید: همهٔ متن‌ها باید همچنان فارسی و کنترل‌ها راست‌به‌چپ باشند.
- جابه‌جایی، زوم حول دو انگشت، محدودیت زوم و بازنشانی را بررسی کنید.
- صفحه را بچرخانید: نمای فعلی باید حفظ شود.
- حالت تیره و اندازهٔ قلم بزرگ را بررسی کنید؛ دکمه‌های کنترل حداقل ۴۸dp هدف لمسی دارند.
- بدون اینترنت اپ را باز کنید؛ بوم باید کار کند.

این فهرست برای آزمون دستی است؛ موفقیت ساخت ابری به‌تنهایی تأیید آزمون روی گوشی واقعی نیست.
